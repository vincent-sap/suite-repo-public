# Update from Suite Replica

Pull upstream changes into the user's fork. Non-technical audience. Two hard rules:
**keep the user's own changes** (merge in only upstream's updates) and **never push** — the user reviews and pushes themselves.

1. `git status --short`. If anything is uncommitted, STOP and ask (AskUserQuestion): commit / discard / stop. Tree must be clean first — that's how we tell fork changes from upstream's.
2. Confirm this is a fork: compare `git remote get-url origin` with `https://github.tools.sap/signavio-experience/suite-replica.git`. If they're the **same**, this is the main repo, not a fork — STOP and tell the user: "You're in the original suite-replica, not a fork — there's nothing to update from. This skill is for forks." Do not add the upstream remote or merge.
3. Ensure remote: `git remote get-url upstream || git remote add upstream https://github.tools.sap/signavio-experience/suite-replica.git`
4. `git fetch upstream && git checkout main && git merge upstream/main`
5. Conflicts — cheapest first, don't read files you don't need to:
   - `docs/**` → `git checkout --ours -- <files> && git add` (generated, rebuilt in step 6 — never read)
   - `package-lock.json` → `git checkout --ours && git add` (regenerated by npm install)
   - anything else → read only the conflict hunks (`git diff <file>`), merge by hand keeping the fork's intent AND upstream's update; never blindly drop a side. Then `git commit --no-edit`.
6. `npm install && npm run build`, then `git add docs/ && git commit -m "chore: rebuild docs"`. 401 → remind about Artifactory login. Build fails → show error and STOP.
7. Hand off for review — do NOT read the full diff, just surface it: run `git log --oneline origin/main..HEAD` and `git diff --stat origin/main..HEAD`, summarise in plain words (what came in + any conflicts you resolved and how), then tell the user to review and push themselves with `git push origin main`. Never push.
